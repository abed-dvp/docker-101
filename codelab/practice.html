HANDS-ON PRACTICE

Docker 101 — Step-by-Step Lab

Run these commands on your own machine, in order. Do not just read them. Mark each step complete only after you have actually run it and understood the result.

0 / 12 complete
Open repository ↗
STEP 1

Verify Docker works

Goal: verify both the Docker CLI and Docker Engine.

docker --version
docker run hello-world
docker ps -a
Mental model
Image → container created → process runs → process finishes → container remains in stopped/exited state.

Check yourself: why does hello-world disappear from docker ps but still appear in docker ps -a?

STEP 2

Pull a ready-made image

docker pull nginx:1.27
docker images
Registry → docker pull → local image cache.

Confirm that nginx is the repository/image name and 1.27 is the tag.

STEP 3

Create a container and publish a port

docker run --name practice-nginx -p 8080:80 -d nginx:1.27
docker ps

Open http://localhost:8080.

Browser → localhost:8080 → Docker port mapping → container:80 → nginx.
STEP 4

Use logs and exec

docker logs practice-nginx
docker exec -it practice-nginx sh

pwd
ls
nginx -v
exit
docker exec does not create a new container. It runs another process inside the existing running container.
STEP 5

Practice the lifecycle

docker stop practice-nginx
docker ps
docker ps -a
docker start practice-nginx
docker restart practice-nginx
docker stop practice-nginx
docker rm practice-nginx
run → new container · start → existing container · rm → delete container.
STEP 6

Read your Dockerfile

FROM node:20-alpine

WORKDIR /app
COPY package*.json ./
RUN npm install --omit=dev
COPY server.js .
EXPOSE 3000
CMD ["npm", "start"]

Explain every line before continuing. Especially: RUN happens during build; CMD runs when a container starts.

STEP 7

Build your own image

docker build -t docker-101-app:1.0 .
docker images
Dockerfile + build context → docker build → image.
STEP 8

Run your own image

docker run --name docker-101-web -p 3000:3000 -d docker-101-app:1.0
docker ps
curl http://localhost:3000/health

Open http://localhost:3000 and http://localhost:3000/health.

STEP 9

Inspect your own container

docker exec -it docker-101-web sh

pwd
ls
node --version
cat server.js
exit

You should see /app, Node 20, and the source code copied into the image/container filesystem.

STEP 10

Observe build cache

Change the message in server.js, then:

docker build -t docker-101-app:1.1 .

Watch which Dockerfile steps use cache. package.json did not change, so dependency installation may be reused.

Stable dependency files first → expensive install layer → frequently changing source later.
STEP 11

Run the new image version

docker stop docker-101-web
docker rm docker-101-web
docker run --name docker-101-web -p 3000:3000 -d docker-101-app:1.1

Open http://localhost:3000 and confirm the changed message.

New image ≠ automatic update of an existing container. Create a new container from the new image.
STEP 12

Run the project with Docker Compose

docker stop docker-101-web
docker rm docker-101-web

docker compose up --build -d
docker compose ps
docker compose logs app
docker compose exec app sh

printenv PORT
exit

docker compose down
Manual docker build + long docker run configuration → encoded as docker-compose.yml + docker compose up.
